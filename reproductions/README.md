# 复现实验总览

三个实验全部成功。本目录的全部结论满足以下可验证性要求:

- **密码学正确性锚定**: `sca_common.js` 中的 AES-128 实现在模块加载时自动运行两个官方已知答案测试(FIPS-197 附录 C.1 与 NIST SP 800-38A F.1.1 的 ECB-AES128 向量),任一失败即抛异常——任何脚本都不可能在 AES 实现错误的情况下运行
- **完全可复现**: 所有随机性来自固定种子的确定性 PRNG(mulberry32 + Box-Muller),任何人重跑得到逐位一致的结果
- **目标密钥公开**: 使用 NIST SP 800-38A 公开测试向量密钥 `2b7e151628aed2a6abf7158809cf4f3c`(仅作演示目标,无保密意义)
- **运行环境**: Node.js v24.16.0, Windows;`node <脚本名>` 即可重跑

## 实验 1: AES-128 相关性功耗分析(CPA)— `cpa_aes.js`

**方法来源**: Brier, Clavier, Olivier, "Correlation Power Analysis with a Leakage Model", CHES 2004(三位作者——注意常见引用误加 Walter,经 Crossref 核实仅此三人;详见 `../knowledge/01-power-analysis/`)。

**设定**: 20 个采样点的功耗轨迹(16 个第一轮 SBox 汉明重量泄漏点 + 4 个纯噪声点),高斯测量噪声;攻击者只知明文与轨迹,不知密钥与泄漏点位置,逐字节做 256 假设 × 全点 Pearson 相关枚举。

**主演示结果(N=300, σ=1.0)**:

- **16/16 字节全部正确,完整恢复 128 位密钥**(耗时 0.1s)
- 正确假设相关性 r ≈ 0.79–0.85,最优错误假设 r ≈ 0.21–0.29,边际 ≥ 0.52——排除偶然
- 理论对照: HW 泄漏下 r ≈ √(Var_HW/(Var_HW+σ²)) = √(2/3) ≈ 0.816,实测 0.80–0.85,吻合

**鲁棒性研究(σ × N,20 个配置)**:

| σ\N | 50 | 100 | 300 | 500 |
|---|---|---|---|---|
| 0 | 16/16 | 16/16 | 16/16 | 16/16 |
| 0.5 | 16/16 | 16/16 | 16/16 | 16/16 |
| 1.0 | 16/16 | 16/16 | 16/16 | 16/16 |
| 2.0 | 14/16 | 16/16 | 16/16 | 16/16 |
| 3.0 | 6/16 | 11/16 | 16/16 | 16/16 |

呈现经典相变:噪声越大,所需轨迹数越多。**结论**: 该方法的统计核心被完整复现且与理论定量吻合。

## 实验 2: 字节级计时攻击 + 恒定时间防御对照 — `timing_attack.js`

**方法来源**: Kocher, "Timing Attacks on Implementations of Diffie-Hellman, RSA, DSS, and Other Systems", CRYPTO 1996;Brumley & Boneh, "Remote Timing Attacks are Practical", USENIX Security 2003(元数据验证见 `../knowledge/03-timing-cache-microarch/`)。场景与 Cryptopals Set 4 Challenge 31/32 同型(经核实计时挑战位于 Set 4,常被误记为 Set 7)。

**设定**: 漏洞比较函数每匹配 1 字节增加 0.25ms 工作量(提前返回),含 σ=0.05ms 高斯抖动;攻击者逐位置对 256 候选测耗时。

**最终结果**: **8/8 字节完全恢复**(40,960 次测量,36s),每位置的中位数最优/次优边际 0.17–0.22ms,清晰对应 0.25ms 的单位信号。

**迭代记录(方法学上有价值的失败)**:

1. **v1(少样本均值, k=10): 失败**——位置 6/7 恢复错误。原因: 毫秒级的 GC/调度停顿离群值足以污染均值(均值对离群值敏感,而信号只有 0.25ms)。这不是仿真假象——真实远程计时攻击(Brumley-Boneh)同样要对抗网络抖动离群值,文献中的对策正是大样本量与稳健统计量
2. **v2(中位数, k=20, 复用 Buffer 减少 GC): 成功**——中位数对 <50% 的离群样本完全免疫
3. 另发现并修正一个**纯打印层的单位 bug**(ms 被再乘 1000,一度显示"边际 210ms";实际 0.21ms,与信号吻合)。此 bug 不影响攻击逻辑,记录在此防止结果被误读

**防御对照**: `crypto.timingSafeEqual` 在 0–8 字节匹配前缀下平均耗时 0.16–0.42µs、无单调趋势(极差 0.19µs,比漏洞版信号小 3 个数量级)——恒定时间比较无计时信号,攻击无从下手。

## 实验 3: TVLA 泄漏检测 + 一阶掩码有效性 — `tvla_masking.js`

**方法来源**: Goodwill, Jun, Jaffe, Rohatgi, "A Testing Methodology for Side-Channel Resistance Validation", NIST Non-Invasive Attack Testing Workshop 2011(注意:该文常被误引为"CHES 2011",经核实为 NIST NIAT workshop 论文);一阶布尔掩码思想来自 Ishai, Sahai, Wagner, CRYPTO 2003(ISW)(元数据验证见 `../knowledge/05-countermeasures-evaluation/`)。

**设定**: 固定明文组 vs 随机明文组各 1000 条轨迹(σ=0.75),逐点 Welch t 检验,|t|>4.5 报警,3 个固定向量取 max|t|。对照两种实现: 未掩码 `L=HW(SBox[p⊕k])` vs 一阶掩码 `L=HW(SBox[p⊕k]⊕m)+HW(m)`(x 拆为两份 share)。

**结果**:

| 实现 | 一阶 t 检验 | 二阶(方差)检验 | 一阶 CPA(N=500) |
|---|---|---|---|
| 未掩码 | **16/16 SBox 点报警**(\|t\| 19–71) | — | 16/16 密钥恢复(实验1) |
| 一阶掩码 | **0/20 点报警**(\|t\| ≤ 2.4,通过) | **14/16 SBox 点报警**(\|t\| 最高 19.6) | 0/16 首位命中,排名散布如随机 |

**理论解释与结论**: 掩码后 E[HW(x⊕m)+HW(m)] 与 x 无关(一阶矩恒定)→ 一阶检验通过与一阶 CPA 失效,复现了 ISW 掩码的安全证明预期;但方差 = 8−HW(x) 仍依赖秘密 → 二阶统计量检出,对应真实世界"一阶掩码挡不住高阶攻击"。**评估启示**: TVLA 一阶通过 ≠ 安全,评估必须覆盖高阶统计量与攻击性验证——这正是本实验用两个统计量交叉验证所演示的。

## 边界与诚实声明

- **仿真泄漏模型 ≠ 真实硬件**: 本实验未包含真实采集中的毛刺(glitch)、时钟漂移、轨迹失配、放大器非线性等效应;但区分器设计、假设检验、泄漏模型、稳健统计这些**方法学核心与真实场景同构**,且可被任何人零成本重跑验证
- **硬件复现路径**: ChipWhisperer(开源工具链 + 低成本采集硬件,见 `../knowledge/07-tools-datasets/`)是标准入门路径,路线图中列为后续阶段
- **用途边界**: 仅用于授权安全研究、防御评估与教学
